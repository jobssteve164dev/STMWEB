# STMWEB 通用设备远程控制网关设计

## 1. 目标

STMWEB 增加一套按工作区隔离的通用设备远程控制基础设施，使用户可以：

1. 注册自己拥有的联网设备；
2. 查看设备是否在线以及能够完成哪些动作；
3. 决定哪些应用可以查看或调用哪些设备能力；
4. 从网页、CLI、自动化平台、智能体或其他客户端调用设备；
5. 得到设备真实执行后的进度、结果和审计记录。

机器狗只是第一台验证设备，不是产品边界。STM32、ESP32、Linux 机器人、树莓派、家庭设备、边缘网关以及通过本地 Device Agent 接入的传统硬件都应能够使用同一套公共契约。

本设计的用户语言始终是：

> 注册设备、允许应用调用、调用设备、查看结果。

南向供给者、北向消费者、租约、路由和协议适配是内部架构概念，不应成为普通用户完成动作的前置知识。

## 2. 成功标准

第一版完成后，必须能够通过真实链路证明：

- 用户在自己的工作区注册一台设备，设备不需要开放公网入站端口；
- 设备使用独立机器身份保持在线并声明可调用能力；
- 用户可以创建一个限定到该工作区、设备和动作的消费侧授权；
- 任意遵循公共契约的消费侧可以创建一次设备调用；
- 设备领取同一个操作、执行并回传明确终态；
- 消费侧通过稳定 `operation_id` 读到真实结果，而不是只知道请求已经发送；
- 网络重试不会导致同一个物理动作被重复执行；
- 设备离线、超时、拒绝、断线和取消都有明确状态；
- 其他工作区不能发现、领取、调用或读取该设备及其操作；
- STMWEB 网页与外部消费侧使用同一业务能力和同一事实源。

## 3. 不在第一版范围内

第一版不把设备网关扩展为任意远程执行或通用媒体平台，不包含：

- 任意 Shell、脚本或未声明方法的远程执行；
- 调用者提交任意回调 URL 或任意目标地址；
- 摄像头实时视频、持续音频或其他大流量媒体转发；
- 通用消息队列、通用 IoT Broker 或 MQTT 托管服务；
- 将固件上传、烧录和安全升级伪装成普通设备动作；
- 绕过设备本地急停、限速、电量和机械安全约束；
- MCP、CloudMCP、Codex、GitOps 或其他消费平台专属协议；
- 承诺唤醒已经断电或网络模块完全休眠的设备。

固件构建和升级继续使用其已有的制品、摘要、目标校验和恢复边界。未来可以共享设备身份和审计链，但不与普通动作共用不受约束的载荷通道。

## 4. 第一性原则

### 4.1 用户只面对设备和动作

界面与用户文档从用户要完成的动作出发，不从内部对象出发。用户看到“注册设备”“这台设备能做什么”“允许这个应用调用”“设备正在执行”，而不是 Provider、Consumer、Bridge、Lease 或 Adapter。

### 4.2 STMWEB 定义中立公共契约

STMWEB 是设备、能力、授权、操作、事件和结果的唯一业务事实源。网页、CLI、自动化平台、智能体和第三方应用都是平等的消费侧，不因接入方式不同获得隐藏能力。

### 4.3 南北向身份严格分离

- 北向凭证代表用户授权的消费侧，只能创建和读取获准的设备操作；
- 南向凭证代表一个设备供给连接，只能上报和执行它负责的设备；
- 南向凭证不能代表用户调用其他设备；
- 北向凭证不能伪造设备执行结果。

### 4.4 可靠结果优先于请求转发

网关不是把 JSON 转发给设备后立即宣布成功。一次调用只有在设备回报 `succeeded` 后才算完成。排队、领取、接收、执行、失败、取消和过期都是可查询的业务事实。

### 4.5 通用不等于任意

设备通过版本化能力声明提供受约束的动作。STMWEB 校验动作名称、参数、大小、有效期和授权，不提供任意代码、任意网络代理或无法审计的透明透传。

### 4.6 设备本地安全最终生效

服务端控制权限不能解除设备本地安全条件。急停、限速、机械边界、电池阈值和重复操作去重必须在设备或 Device Agent 上最终执行。

## 5. 系统关系

```text
南向设备供给

联网硬件 ──────────────┐
传统硬件 → Device Agent ├─ 注册、心跳、能力、领取操作、回传结果
边缘网关 → 多台设备 ────┘
                         │
                         ▼
              STMWEB 设备远程控制网关
       工作区 + 设备 + 能力 + 授权 + 操作 + 审计
                         ▲
                         │
网页 / CLI / 用户服务 / 自动化 / Agent / MCP Adapter

北向授权消费
```

STMWEB 不发现或反向编排消费侧平台。用户在自己选择的消费侧中使用经过授权的公共 API。消费侧采用 MCP、SDK、REST、工作流节点还是其他协议映射，均不改变 STMWEB 的对象和状态。

## 6. 内部概念与用户语言

| 内部概念 | 含义 | 用户语言 |
| --- | --- | --- |
| Device Provider | 负责联网、能力上报和操作执行的南向身份 | 不展示 |
| Device | 用户拥有和调用的真实设备 | 设备 |
| Enrollment | 建立工作区、Provider 与设备归属关系 | 注册设备 |
| Capability Manifest | 设备声明的动作、参数和状态 | 设备能做什么 |
| Consumer Connection | 某个北向客户端的授权身份 | 应用连接 |
| Device Grant | 消费侧可以访问的设备和动作范围 | 允许应用调用 |
| Device Operation | 一次可追踪的设备调用 | 调用设备 |
| Lease | 把操作临时分配给正确 Provider | 正在发送给设备 |
| Operation Event | 调用过程中的有序状态变化 | 调用进度 |
| Terminal Result | 设备回报的最终结果 | 已完成或未完成 |

内部术语可以用于代码、协议和运维文档，但不能要求普通用户先理解这些对象才能使用产品。

## 7. 租户、归属与成员权限

### 7.1 工作区是租户边界

设备、Provider、消费侧连接、设备授权、操作和事件都必须归属于一个 `workspace_id`。所有读取和写入都必须同时验证工作区，不能只凭全局 UUID 访问对象。

现有成员角色沿用：

- `owner`：注册、配置、授权、调用、解绑设备；
- `editor`：在工作区策略允许时注册、配置和调用设备；
- `viewer`：只能查看设备、能力和获准的操作记录。

第一版允许一个设备只归属于一个工作区。设备转移必须由原工作区显式解绑或通过受控的所有权恢复流程完成，不能仅凭设备序列号重新认领。

### 7.2 Provider 与设备分离

Provider 是执行连接，设备是用户资源。一个 Provider 可以提供一台或多台设备，例如一个家庭 Device Agent 可以代理机器狗、灯和音箱。

第一版约束：

- 一台设备只有一个当前有效 Provider 路由；
- 一个 Provider 可以注册多台设备；
- Provider 被撤销时，其设备转为离线，但设备台账和历史操作保留；
- Provider 不能把设备移动到另一个工作区；
- 主备 Provider、多路径路由和自动故障切换延后设计。

## 8. 核心业务对象

### 8.1 Device Provider

保存南向执行连接的身份和状态，至少包含：

- `id`
- `workspace_id`
- `name`
- `credential_hash`
- `credential_version`
- `status`
- `last_seen_at`
- `revoked_at`
- `created_by`
- `created_at`

机器凭证只在签发时显示一次，服务端只保存哈希。凭证支持轮换和撤销。

### 8.2 Device

沿用现有设备台账，并增加远程执行需要的状态：

- `provider_id`
- 稳定设备标识与显示名称
- `connection_mode`，例如 `remote` 或已有近场连接方式
- `status` 与 `last_seen_at`
- `firmware_version`
- 当前能力版本
- 当前操作 ID
- `registered_at` 与 `disconnected_at`

用户界面不因 `connection_mode` 拆出不同设备对象。近场连接和远程连接仍然是“我的设备”的不同连接条件。

### 8.3 Capability Manifest

能力声明需要版本化持久化，至少包含：

- schema 版本；
- manifest 版本和内容摘要；
- 设备与固件版本；
- 动作稳定名称；
- 输入 JSON Schema；
- 结果 JSON Schema；
- 建议超时和最大超时；
- 是否允许并行；
- 是否可以被当前操作打断；
- 用户可理解的动作名称和说明；
- 能力在线、降级或不可用状态。

示例：

```json
{
  "schemaVersion": 1,
  "manifestVersion": "2026-08-20.1",
  "device": {
    "id": "device-123",
    "model": "robot-dog-v1",
    "firmwareVersion": "1.0.0"
  },
  "actions": [
    {
      "name": "speech.say",
      "label": "说话",
      "inputSchema": {
        "type": "object",
        "additionalProperties": false,
        "properties": {
          "text": { "type": "string", "minLength": 1, "maxLength": 500 }
        },
        "required": ["text"]
      },
      "resultSchema": {
        "type": "object",
        "properties": {
          "durationMs": { "type": "integer", "minimum": 0 }
        }
      },
      "defaultTimeoutMs": 15000,
      "maximumTimeoutMs": 30000,
      "interruptible": true
    },
    {
      "name": "motion.play",
      "label": "做动作",
      "inputSchema": {
        "type": "object",
        "additionalProperties": false,
        "properties": {
          "preset": { "type": "string", "enum": ["wake", "wave", "nod"] }
        },
        "required": ["preset"]
      },
      "defaultTimeoutMs": 10000,
      "maximumTimeoutMs": 20000,
      "interruptible": true
    }
  ]
}
```

第一版语音传递文字，由设备或 Device Agent 本地完成 TTS；不在普通操作中传输音频文件。

### 8.4 Consumer Connection 与 Device Grant

现有 `api_connections` 可以继续作为北向连接身份基础，但需要支持用户明确选择工作区，并将授权进一步收窄到设备和动作。

授权关系至少包含：

- `connection_id`
- `workspace_id`
- 可访问的设备集合，或明确的工作区全设备授权；
- 每台设备允许的动作集合；
- 读取、调用、管理等权限；
- 生效与到期时间；
- 撤销状态；
- 授权人与更新时间。

能力声明只表示设备能够执行，不自动授予任何消费侧调用权。消费侧权限只能由用户授权产生。

### 8.5 Device Operation

一次调用是南北向贯通的唯一稳定对象，至少包含：

- `id`，即稳定 `operation_id`；
- `workspace_id`
- `device_id`
- `provider_id`
- `action`
- 经过校验的参数；
- `status`
- `idempotency_key`
- 发起用户与可选 `connection_id`
- `created_at`、`expires_at`
- `lease_id`、`leased_at`、`lease_expires_at`
- `accepted_at`、`started_at`、`finished_at`
- 结构化结果或稳定错误码；
- 可选 `trace_id`。

操作事件独立保存，使用每个操作内单调递增的序号和幂等事件 ID。

## 9. 操作状态机

```text
queued
  │
  ├─ 到达有效期 ─────────────────────────→ expired
  ├─ 用户取消 ───────────────────────────→ cancelled
  ▼
leased
  │
  ├─ 租约超时且操作仍有效 ───────────────→ queued
  ├─ 用户请求取消 ───────────────────────→ cancelling
  ▼
accepted
  │
  ├─ 设备拒绝参数或本地安全条件不满足 ──→ failed
  ├─ 用户请求取消 ───────────────────────→ cancelling
  ▼
running
  │
  ├─ 用户请求取消 ───────────────────────→ cancelling
  ├─ 执行失败 ───────────────────────────→ failed
  └─ 设备明确回报完成 ───────────────────→ succeeded

cancelling
  ├─ 设备确认已经停止 ───────────────────→ cancelled
  ├─ 动作无法中断但最终完成 ─────────────→ succeeded
  └─ 停止或执行失败 ─────────────────────→ failed
```

约束：

- `succeeded`、`failed`、`cancelled`、`expired` 是终态；
- 只有设备侧可以把已经投递的操作推进到 `accepted`、`running` 和执行终态；尚未投递的排队操作可以由服务端安全取消或过期；
- 北向消费侧只能创建操作、读取状态和请求取消；
- 同一设备第一版同时只允许一个普通控制操作；
- `stop` 等本地安全动作可以拥有高优先级并打断可中断操作；
- 已过期操作永不再次投递；
- 设备断线后，未过期且尚未被设备接收的操作可以继续排队；
- 设备已经接收但未回报终态时，界面必须显示结果未知，不能推断成功。

## 10. 投递、幂等与断线恢复

网络无法提供真正的只投递一次。第一版采用“至少一次投递、操作效果幂等”的模型：

1. 北向创建操作时提供 `Idempotency-Key`；
2. STMWEB 在同一工作区、调用主体和幂等键下返回同一个 `operation_id`；
3. Provider 使用租约领取操作；
4. 设备或 Device Agent 持久化最近执行过的 `operation_id`；
5. 重复收到同一操作时不重复驱动硬件，而是返回已保存状态或结果；
6. 事件使用稳定事件 ID 和序号，重复提交不会产生重复状态变化；
7. 租约过期只允许尚未确认执行的操作重新入队；
8. 已进入 `running` 但失联的操作保持结果未知，直到设备恢复后补报结果或达到操作终止策略。

设备端去重是物理动作不被重复执行的最终保障，不能只依赖服务端请求去重。

## 11. 南向设备供给契约

第一版使用设备主动出站的 HTTPS 长轮询，不要求设备开放入站端口，也不先引入 MQTT、Redis 或独立消息 Broker。长轮询请求可以在服务端等待短时间，有操作时立即返回，无操作时正常结束并重新建立。

建议采用独立版本入口 `/api/device/v1`，避免与用户会话或北向授权混用。

### 11.1 注册

```text
POST /api/v1/workspaces/:workspaceId/device-enrollments
POST /api/device/v1/enrollments/exchange
POST /api/device/v1/devices
```

第一步由已登录用户创建短时、一次性的注册材料；第二步由 Provider 交换机器凭证；第三步由已认证 Provider 注册它实际提供的设备。注册材料不得直接成为长期设备凭证。

### 11.2 心跳与能力

```text
POST /api/device/v1/heartbeat
PUT  /api/device/v1/devices/:deviceId/capabilities
```

心跳只允许更新 Provider 负责的设备。在线状态由最近心跳和服务端时间计算，不能由设备任意声明永久在线。

### 11.3 领取与续租

```text
POST /api/device/v1/operations/lease
POST /api/device/v1/operations/:operationId/renew
```

领取查询必须同时约束 `provider_id + workspace_id + device_id`，并使用数据库事务与 `FOR UPDATE SKIP LOCKED` 防止重复分配。

### 11.4 事件和结果

```text
POST /api/device/v1/operations/:operationId/events
```

Provider 必须提交租约身份、事件 ID、序号、状态和结构化载荷。服务端验证状态迁移，不能允许任意状态覆盖。

## 12. 北向授权消费契约

北向继续使用版本化 `/api/v1`，业务对象不包含任何消费平台专属字段。

```text
GET  /api/v1/workspaces/:workspaceId/devices
GET  /api/v1/workspaces/:workspaceId/devices/:deviceId
GET  /api/v1/workspaces/:workspaceId/devices/:deviceId/capabilities

POST /api/v1/workspaces/:workspaceId/devices/:deviceId/operations
GET  /api/v1/workspaces/:workspaceId/device-operations/:operationId
POST /api/v1/workspaces/:workspaceId/device-operations/:operationId/cancel
GET  /api/v1/workspaces/:workspaceId/device-operations/:operationId/events
```

创建操作示例：

```http
POST /api/v1/workspaces/{workspaceId}/devices/{deviceId}/operations
Authorization: Bearer <user-authorized-credential>
Idempotency-Key: <stable-client-generated-key>
Content-Type: application/json
```

```json
{
  "action": "speech.say",
  "arguments": {
    "text": "任务已经完成，请来看一下。"
  },
  "executionTimeoutMs": 15000,
  "expiresInMs": 30000,
  "queueIfOffline": true
}
```

响应必须返回操作资源：

```json
{
  "operation": {
    "id": "operation-456",
    "deviceId": "device-123",
    "action": "speech.say",
    "status": "queued",
    "createdAt": "2026-08-20T16:00:00.000Z",
    "expiresAt": "2026-08-20T16:00:30.000Z"
  }
}
```

HTTP 成功只表示操作已被网关接受，不等于设备执行成功。客户端必须根据操作状态判断结果。

### 12.1 同步体验与异步事实

底层 API 始终创建持久化操作。SDK 或消费侧适配器可以提供有限等待：

- 短动作在等待窗口内完成时直接返回终态；
- 尚未完成时返回 `operation_id` 和当前状态；
- 客户端后续读取同一操作；
- 不通过无限阻塞请求掩盖离线或长时间动作。

### 12.2 事件订阅

第一版以查询操作状态为必需路径。通用 webhook 或事件订阅可以作为后续兼容扩展，但必须：

- 由用户为某个消费侧连接显式启用；
- 继续受工作区、设备和动作授权限制；
- 使用签名、时间戳和重放保护；
- 使用稳定事件 ID，允许消费侧幂等处理；
- 不包含 MCP 或其他平台专属回调格式。

## 13. 北向认证与授权

### 13.1 第一版

复用现有用户 API 连接作为个人访问凭证，但补齐：

- 创建时明确选择工作区；
- `devices:read`：查看设备、能力和获准操作；
- `devices:manage`：注册、配置、授权和解绑设备；
- `devices:control`：创建与取消设备操作；
- 可选设备和动作范围；
- 可选有效期；
- 凭证轮换、撤销和最近使用记录。

当前 `devices:control` 只对应“登记设备”的实现需要拆分，不能让登记台账和驱动物理设备共享含混授权文案。

### 13.2 第三方应用

面向第三方在线应用时，增加标准授权码流程和短期 access token，使用户在 STMWEB 中选择工作区、设备和动作，不要求用户把个人长期凭证交给第三方。

消费侧授权只能收窄用户本来拥有的权限，不能通过提交 `user_id`、工作区名称或设备 ID 切换调用身份。

## 14. 南向认证与注册安全

- 注册材料一次性、短时有效，并在交换时使用事务锁定；
- Provider 凭证使用高强度随机值，服务端只保存哈希；
- Provider 凭证绑定工作区和 Provider，不能跨租户使用；
- 每次设备领取、续租和回报都验证 Provider 对设备的当前归属；
- 轮换后旧凭证立即失效；
- Provider 撤销或设备解绑后不能继续领取新操作；
- 设备序列号、MAC 地址或公开硬件 ID 不能单独证明所有权；
- 恢复出厂设置不能自动转移云端归属；
- 量产阶段可以增加设备证书、安全芯片或 mTLS，但不阻塞第一版强随机凭证闭环。

## 15. 物理动作安全

用户可以在注册或授权时设置“允许自动调用”的动作集合，避免每次低风险通知都需要人工确认。高风险动作可以由设备能力或工作区策略要求额外确认。

第一版必须满足：

- 操作有明确 TTL，过期后设备不得执行；
- 同一设备默认串行执行普通操作；
- `stop` 或等价急停动作可以高优先级处理；
- 设备只执行当前能力声明中存在且参数校验通过的动作；
- 参数长度、数字范围、动作持续时间和载荷大小受到限制；
- 本地安全条件拒绝操作时回报稳定错误码；
- 服务端断线、租约过期或重复投递不能解除本地安全状态；
- 不通过普通动作下发任意固件、脚本或可执行文件。

## 16. 离线、休眠与唤醒语义

用户所说的“唤醒设备”必须对应真实网络能力：

- 设备在线待机：操作可以秒级送达；
- 网络模块在线、主控休眠：由设备本地网络模块唤醒主控；
- 周期联网：操作等待下一次设备轮询；
- 断电或网络模块完全休眠：STMWEB 无法主动唤醒。

创建操作时由调用者选择是否允许离线排队，并始终设置较短有效期。界面使用自然状态：

- “正在发送给设备”对应排队或分配；
- “设备已收到”对应 `accepted`；
- “设备正在执行”对应 `running`；
- “设备离线，正在等待”对应允许离线排队；
- “等待时间已过，本次未执行”对应 `expired`。

不能把过期操作留到设备数小时后上线时突然执行。

## 17. 用户体验

### 17.1 注册设备

1. 用户点击“注册设备”；
2. STMWEB 显示配对码、二维码或适合该设备的注册材料；
3. 用户在硬件或 Device Agent 上完成一次配对；
4. 页面显示设备已连接以及设备能做什么；
5. 用户选择哪些动作可以被应用自动调用。

页面不要求用户选择 Provider 类型、租约方式或消费平台协议。

### 17.2 允许应用调用

用户建立自然授权关系，例如：

> 允许“我的电脑助手”调用“书房机器狗”的“说话”和“点头”。

界面呈现用户动作，而不是直接暴露 scope 字符串、资源 grant 或数据库对象。

### 17.3 调用与结果

网页和外部消费侧使用相同状态，面向用户显示：

- 正在发送给设备；
- 设备已收到；
- 设备正在执行；
- 已完成；
- 设备拒绝了这个动作；
- 设备离线，正在等待；
- 等待时间已过，本次未执行；
- 结果未知，设备恢复连接后继续确认。

普通用户界面不得直接显示 `provider unavailable`、`lease expired` 或内部状态迁移错误。

## 18. 隐私、数据和审计

- 语音文字可能包含用户任务和私人内容，只保存完成操作所需的数据；
- 操作参数和结果设置明确保留周期，过期后可以保留不可逆摘要和非敏感审计元数据；
- 最近调用页面默认显示动作摘要，不完整复制敏感正文；
- 日志不得包含凭证、完整授权头或未脱敏的私人数据；
- 第一版不默认上传麦克风、摄像头、环境录音或持续遥测；
- 每次北向调用记录连接、工作区、设备、动作、`operation_id`、结果和时间；
- 每次南向状态变化记录 Provider、设备、操作、事件 ID 和时间；
- 撤销连接或设备凭证不删除既有业务和审计记录。

## 19. 公共契约治理

南北向契约均由 STMWEB 定义并版本化：

- 提供机器可读 OpenAPI；
- 同一主版本只做向后兼容扩展；
- 客户端容忍未知响应字段和未知可忽略事件；
- 状态和错误使用稳定代码，用户文案由最终界面本地化；
- 所有创建操作支持幂等键；
- 所有跨系统动作透传稳定 `operation_id`，可选 `trace_id`；
- 分页、时间、大小、超时和重试语义写入契约；
- 不因某个消费侧要求增加产品专属字段、请求头或协议版本；
- MCP 或其他适配器只能调用公共 API，不能直接访问 STMWEB 数据库或内部模块。

## 20. 与当前实现的衔接

### 20.1 可以复用

- SZLKPassport 用户身份和本地用户映射；
- 工作区、成员角色和应用层工作区校验；
- `api_connections` 的凭证哈希、轮换、撤销和审计基础；
- `/api/v1` 中立用户 API 入口；
- Runner 一次性配对、机器令牌、出站心跳、事务租约和幂等事件的实现经验；
- 现有设备台账和能力驱动界面的用户心智。

### 20.2 不能直接复用为设备模型

- `build_runners` 只表示编译算力，不能改名或扩字段后充当通用 Device Provider；
- `build_jobs` 状态、源码和制品字段不能承载设备动作；
- 浏览器能力组件类型不能代替可执行动作 schema；
- 调试事件不能伪装成远程操作终态；
- 旧 `/api/provider-bridge` 和 `cloudmcp-provider.ts` 不能成为设备网关入口或事实源。

### 20.3 需要新增

- Provider 注册、身份、心跳和撤销；
- Provider 与设备归属关系；
- 版本化能力声明与摘要；
- 消费侧设备和动作授权；
- 设备操作、租约、事件、结果和幂等约束；
- 南向机器 API；
- 北向设备调用 API；
- 普通用户可用的注册、授权、调用和历史界面；
- 南北向越权、重试、断线和状态机测试。

## 21. 第一版交付切片

### 21.1 最小功能

1. 用户在个人工作区创建一次设备注册；
2. 一个电脑端模拟 Device Provider 使用注册材料换取机器凭证；
3. Provider 注册一台“通知设备”，声明 `speech.say` 和 `motion.play`；
4. 用户创建一个只允许调用该设备两个动作的消费侧连接；
5. 独立测试客户端通过 `/api/v1` 创建操作；
6. Provider 通过 HTTPS 长轮询领取操作；
7. Provider 回报 `accepted`、`running` 和 `succeeded`；
8. 客户端读取同一个 `operation_id` 的完整终态和事件；
9. 重放相同幂等键不会创建或执行第二个操作；
10. 将模拟执行端替换为真实机器狗或第一台联网硬件，完成相同验收。

### 21.2 第一版暂缓

- 第三方 OAuth 应用目录；
- webhook 和实时订阅；
- MQTT；
- Provider 主备和设备多路径；
- 云端 TTS 和音频文件分发；
- 视频流与高频遥测；
- 跨工作区设备共享；
- 复杂计费和配额治理。

暂缓项不能通过专属旁路进入第一版。

## 22. 验证矩阵

### 22.1 正向链路

- 注册材料只能成功交换一次；
- Provider 可注册设备并上报能力；
- 授权消费侧可查看并调用指定动作；
- 在线设备可以领取、执行和回报结果；
- 操作事件顺序稳定且可重复提交；
- 网页与外部客户端读取到同一个操作状态。

### 22.2 租户和权限

- 其他工作区不能列出设备；
- 其他工作区 Provider 不能领取操作；
- 只有 `devices:read` 的连接不能创建设备操作；
- `devices:control` 连接不能调用未获授权设备或动作；
- viewer 不能注册、授权、解绑或调用设备；
- 撤销消费侧连接后后续调用立即失败；
- 撤销 Provider 凭证后不能心跳、领取或回报。

### 22.3 可靠性

- 相同幂等键只产生一个操作；
- Provider 重复领取不会并行执行同一操作；
- 重复事件不会重复推进状态；
- 租约超时后只有符合条件的操作重新排队；
- 已过期操作永不投递；
- 设备在 `running` 状态断线时不被错误标记成功；
- Provider 恢复后可以补报同一操作的终态。

### 22.4 物理设备

- 真实设备完成至少一个语音动作和一个预设动作；
- 本地安全条件拒绝动作时返回稳定错误；
- 相同操作被重复投递时物理动作只执行一次；
- 网络断开和恢复不会触发过期动作；
- 急停可以中断声明为可中断的当前动作。

## 23. 已确认设计决策

- 设备网关是通用基础设施，机器狗只是第一台验收设备；
- 内部采用南向设备供给和北向授权消费模型；
- 普通用户始终使用“注册设备、允许应用调用、调用设备、查看结果”的自然语言；
- MCP 只是消费侧示例，不进入核心契约；
- STMWEB 建立中立、公共、版本化的南北向契约；
- 用户自行决定绑定哪些消费侧，并把授权限制到自己的工作区、设备和动作；
- 工作区是租户隔离边界；
- Provider 与设备是不同内部对象，一个 Provider 可以提供多台设备；
- 设备主动出站，第一版采用 PostgreSQL 与 HTTPS 长轮询；
- 操作必须持久化并由设备回报真实终态；
- 通用能力通过受约束的动作 schema 表达，不允许任意远程执行；
- 用户可预先授权低风险无人值守动作，设备本地安全约束最终生效；
- 新能力只进入中立用户 API 和设备协议，不扩展旧 Provider Bridge。

## 24. 待产品确认但不阻塞第一版原型

- 远程设备网关是否整体属于 Pro 计划；
- 免费用户是否可以从网页控制一台设备；
- 工作区 owner 是否可以限制 editor 的设备控制权；
- 默认离线排队时间和历史数据保留周期；
- 第三方 OAuth 应用开放与审核方式；
- 设备数量、调用频率和事件保留的正式配额。

这些事项影响商业化和治理策略，但不改变南北向公共契约、工作区隔离和统一操作状态模型。
