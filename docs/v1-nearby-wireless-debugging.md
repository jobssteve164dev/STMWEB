# 第一版近距离无线硬件调试设计

## 1. 目标

第一版让用户在智能硬件附近打开 STMWEB，通过浏览器连接设备，自动获得固件与在线硬件提供的调试能力，再由用户选择本次需要的界面组件。平台完成运行态调试数据记录、在线编译制品管理和安全无线升级的完整链路，但不把产品固化为 DOT 小车专用工具。

第一版的“调试”指运行态观测、参数调整、命令控制、日志、编译、烧录和版本确认；断点、单步、寄存器与内存调试保留为后续 `debug-probe` 能力。

## 2. 用户主路径

1. 用户登录并进入工作区。
2. 点击“连接设备”，在浏览器系统选择器中授权附近设备。
3. 平台读取固件能力描述，并用运行状态确认对应硬件是否在线。
4. 平台展示可用组件，预选推荐项；用户决定本次显示哪些组件。
5. 调试台按选择生成，开始会话后持续保存遥测、参数修改和事件。
6. 用户提交源码构建；Homelab x86 Runner 在固定工具链中非交互编译。
7. 用户确认烧录；设备先进入安全停止状态，再接收、校验并启用固件。
8. 设备重启后回报固件版本与能力描述，平台确认升级结果并完成会话记录。

用户始终只理解“连接设备、选择要看的内容、开始调试、编译、烧录”，传输通道、协议适配和多端点关联留在实现层。

## 3. 能力模型

设备通过版本化描述报告能力。稳定能力类型驱动界面组件，设备型号只用于兼容性和台账，不决定页面结构。

```json
{
  "schemaVersion": 1,
  "device": {
    "id": "device-stable-id",
    "model": "hardware-model",
    "firmwareVersion": "1.0.0"
  },
  "capabilities": [
    {
      "id": "imu-main",
      "type": "orientation",
      "label": "姿态",
      "status": "online",
      "channels": ["pitch", "roll", "gyroX", "gyroY", "gyroZ"]
    }
  ]
}
```

识别顺序：

1. 固件自描述是主要事实来源。
2. 运行态探测把能力标记为 `online`、`offline` 或 `degraded`。
3. 旧固件由平台适配器转换为同一能力模型。
4. 无法识别的数据仍可使用通用数值、曲线和终端组件，不通过猜测伪造硬件结论。

第一版组件类型：姿态、摄像头、单/双电机、电池、实时曲线、数值状态、串口终端、参数控制、事件日志、编译与烧录。

## 4. DOT 验证设备映射

DOT 仅作为第一套实物验收设备：

- STM32 USART3 / 蓝牙：运动控制、PID、姿态、电机、电池和升级协议。
- STM32 USART2 / OpenMV：循迹结果输入。
- OpenMV 网络端点：低分辨率图像与视觉识别叠加；现有脚本尚未实现网络视频。
- Homelab x86 Runner：`arm-none-eabi-gcc + CMake/Ninja` 可复现构建。

现有源码的阻断事实：原理图标注 STM32F103C8T6，Keil 工程按 STM32F103CB 链接，当前固件约 81.54 KB。实物容量未确认前禁止无线写入。

## 5. 传输与协议

控制、遥测、能力描述和升级共享逻辑会话，但具有独立消息类型和优先级：

- 安全停止与心跳优先级最高。
- 控制与遥测高于摄像头和历史同步。
- 每帧包含协议版本、类型、序号、长度和 CRC。
- 能力描述在连接、固件重启和硬件状态变化后发送。
- 摄像头使用独立 Wi-Fi 端点；STM32 蓝牙不承载视频。

浏览器 Web Bluetooth 只支持已授权的 BLE GATT 服务。ECB02S2 的 GATT UUID、通知能力、MTU 和吞吐率必须通过实物读取后写入设备适配器。

## 6. 编译和制品

- x86 Linux Runner 使用版本固定的容器镜像。
- 构建输入绑定源码提交、目标 MCU、板卡配置、工具链和构建参数。
- 输出保存 ELF、HEX、BIN、MAP、完整日志、体积报告和 SHA-256。
- Runner 不接触浏览器硬件权限；浏览器取得已批准制品后向附近设备传输。
- C8、CB 是不同目标，超出目标 Flash 或 RAM 时构建直接失败。

## 7. 无线升级和安全

- 设备必须先通过一次有线方式安装不可被普通升级覆盖的恢复 Bootloader。
- 升级前检查设备身份、MCU、Flash、固件签名/哈希、电池电压和电机停止状态。
- 分块传输支持确认、重试和断点恢复；中断后设备仍能进入 Bootloader。
- 第一版不要求 A/B 双分区，但失败不得覆盖恢复 Bootloader。
- 单一控制租约；失联、页面关闭或心跳超时立即清零运动命令。
- 观察、控制、编译和烧录分别授权，全部写入审计会话。

## 8. 数据与工作台

- PostgreSQL 保存设备、固件版本、能力快照、用户选择的组件、调试会话和结构化遥测索引。
- 工作区保存推荐布局，设备可覆盖；每次会话保存实际组件快照。
- 摄像头默认只保存用户截图和异常短片；连续视频进入对象存储，不写入 PostgreSQL 大字段。
- 未连接和演示数据必须明确区分，演示不能作为实物验收证据。

## 9. 第一版验收

必须在真实 DOT 实物上完成一条连续证据链：

1. 浏览器通过 BLE GATT 连接并读取能力描述。
2. 用户选择姿态、电机、电池、终端和摄像头组件，刷新后布局仍保留。
3. 页面持续显示左右电机独立状态、姿态、电池和 OpenMV 画面/识别结果。
4. x86 Runner 从源码非交互构建，平台保存全部制品和体积报告。
5. 无线升级中断可恢复；完整升级后设备回报新版本和能力。
6. 断连、电量不足、型号不符和固件超容时禁止运动或烧录。
7. 会话可回看并导出，演示数据和真实数据不会混淆。

在 ECB02S2 GATT、实物 MCU 容量、OpenMV Wi-Fi 配置未获得实测证据前，平台实现只能达到发布候选，不能宣称真实无线闭环完成。
